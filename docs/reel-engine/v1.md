# Fortune Studio Reel Engine v1.0

## Scope
Reel Engine v1.0 is an additive module under the existing Raven Oracle SNS/Blog/Growth stack. It does not replace the SNS Engine, SNS publishing API, Blog Engine, or Growth Engine.

## Existing Integration Points
- Existing SNS queue: `sns_posts`
- Existing SNS publish flow: `/api/sns/publish` and `/api/admin/sns/publish`
- Existing Blog Engine source content: `blog_engine_articles`
- Existing Blog-to-SNS derivative metadata: `blog_engine_social_contents`
- Existing Growth/Analytics tables remain unchanged

## New Tables
Migrations:

- `drizzle/0006_reel_engine.sql`
- `drizzle/0007_reel_engine_r2_assets.sql`

- `reel_engine_settings`
- `media_video_assets`
- `reel_projects`
- `reel_render_jobs`
- `reel_engine_audit_logs`

All changes are additive. Video binaries are not stored in D1.

## Architecture
Flow:

Blog/SNS/Growth topic -> Reel Project -> Script -> Video Library selection -> Scene Composition -> Text Layers -> Render Job -> Output Asset metadata -> Existing SNS Draft Queue -> Existing SNS approval/scheduler/publish flow.

Core code lives in `app/lib/reel-engine.ts`.

## Provider Interfaces
`VideoRendererProvider` defines:

- `createRenderJob(project)`
- `getRenderStatus(jobId)`
- `cancelRenderJob(jobId)`
- `getOutput(jobId)`

v1.0 ships with a mock/unconfigured provider. If no external renderer is configured, projects, scripts, scenes, text layers, and SNS drafts still work. Rendering returns `unavailable` and does not block the existing SNS Engine.

## Feature Flags / Entitlement
Settings are tenant-scoped in `reel_engine_settings`.

Default plan mapping:

- LIGHT: Reel disabled
- STANDARD: basic Reel creation enabled, AI video generation disabled
- PREMIUM: advanced Reel and AI video generation flags available

API checks are enforced server-side before project creation/rendering.

## API
- `GET /api/reel-engine/library`
- `POST /api/reel-engine/assets` uploads a library asset to R2
- `GET /api/reel-engine/assets?assetId=...` previews a stored asset
- `DELETE /api/reel-engine/assets` deletes an uploaded asset from R2 and soft-deletes its D1 row
- `GET /api/reel-engine/projects`
- `POST /api/reel-engine/projects`
- `PATCH /api/reel-engine/projects`
- `PUT /api/reel-engine/projects` queues a Reel as an existing SNS draft
- `GET /api/reel-engine/render`
- `POST /api/reel-engine/render`

## Admin UI
- `/admin/reels`
- Reel list
- New Reel creation
- Script confirmation
- Scene confirmation
- Text layer confirmation
- Video Library view
- Video Library upload, preview, and uploaded-asset delete
- Render job creation/status
- Approval/status controls
- Existing SNS draft queue handoff

## Environment Variables
None required for v1.0 mock render mode.

R2 asset storage uses a Worker binding named `MEDIA_BUCKET`. The intended bucket name is `raven-oracle-media`.

Do not add the R2 binding to production until R2 is enabled in the Raven Cloudflare account and the bucket exists. The asset API is safe-stopped: when `MEDIA_BUCKET` is missing, upload/preview/delete return HTTP 503 and the rest of Reel Engine continues to work.

Future renderer integration should use server-side secrets only. Do not expose renderer, storage, AI, or social provider keys to the browser.

## R2 Asset Storage
- Accepted uploads: `video/mp4`, `video/webm`, `image/jpeg`, `image/png`, `image/webp`, `audio/mpeg`, `audio/mp4`, `audio/wav`
- Upload limit: 100 MB per file at the application layer
- Object key format: `reel-assets/raven-oracle/{assetId}.{ext}`
- D1 stores metadata only: storage key, MIME type, file size, checksum, category, mood, tags, license type
- Delete is restricted to `source = uploaded`; stock/shared/generated library entries are not removed from this admin screen
- Deletion removes the R2 object and sets `media_video_assets.deleted_at`

## Safety / Cost Controls
- Tenant-scoped entitlement
- Monthly render limit metadata
- Idempotency key on Reel projects
- Duplicate render job guard
- Renderer unavailable fallback
- Audit logs
- Metadata-only D1 storage; binaries stay in R2
- AI video generation disabled unless explicitly entitled

## Known Constraints
- External rendering is not implemented in v1.0; mock provider records unavailable jobs.
- AI video generation is not implemented and remains optional.
- R2 is code-connected, but the Raven Cloudflare account must enable R2 and create/bind the bucket before real uploads work.
- Analytics feedback columns are prepared through metadata and existing SNS/Growth surfaces, but platform metric ingestion depends on social provider availability.

## Rollback
Set `reel_engine_settings.enabled = 0` for the tenant to disable the module without data loss.

For full rollback after backup, drop the additive Reel Engine tables in reverse dependency order:

1. `reel_engine_audit_logs`
2. `reel_render_jobs`
3. `reel_projects`
4. `media_video_assets`
5. `reel_engine_settings`

## Production Release
1. Apply `drizzle/0006_reel_engine.sql` and `drizzle/0007_reel_engine_r2_assets.sql` to D1.
2. Run `npm run build` or `vinext build`.
3. Deploy the Worker with Wrangler.
4. Verify `/admin/reels`, project creation, render unavailable fallback, and SNS draft handoff.
5. After R2 is enabled, create `raven-oracle-media`, add `MEDIA_BUCKET`, redeploy, and verify asset upload/preview/delete.
